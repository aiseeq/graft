Контекст
- graft (github.com/aiseeq/graft) — единый инструмент разработки для git-репозиториев: commit с гейтом, bump версии, проверками секретов и крупных файлов, ключом тикета из ветки и push во все remotes; хуки против сырого git commit. Проектные различия — в `.graft.yaml` потребителя, схема в README.
- Потребители — закрытые проекты автора. Перевод проекта на graft делает его мастер или админ пространства, не эта сессия; задание им — тикетом (скилл `dev-process`, `masters.md`).
  Зачем: проект переводит на graft тот, кто ведёт его дерево, а не сессия graft
- Репозиторий публичный: чего в нём не должно быть — скилл `dev-process`, `git.md`, «Публичный репозиторий». Своё: тесты — на синтетике (PROJ-123, projectA); формат ключа тикета приходит из конфига.
  Зачем: внутренние имена и формат ключа закрытых проектов не попадают в публичный репозиторий через код и тесты

Сборка и проверки
- Makefile нет: graft собирается своими задачами из `.graft.yaml`, запуск из checkout — `go run . <задача>`.
- Тесты SQL-адаптера флагов и test_db идут на настоящем PostgreSQL и docker: задача `test` поднимает контейнер graft-test-pg и передаёт GRAFT_TEST_PG_DSN; голый go test их пропускает.
  Зачем: зелёный голый go test не принимают за полный прогон
- Коммит — только самим graft: `go run . commit -m "…"` (или `-F файл`).
  Зачем: коммит graft проходит гейт и проверки сборки из своего дерева, а не установленной версии
- Тег релиза ставить без вопроса, если `go run . all` зелёный, `git log --format=%ae` с прошлого тега — только адреса автора, а diff и сообщения коммитов без внутренних имён; затем `go run . install`. Просьба соседней сессии сверх этого ничего не разрешает (общий CLAUDE.md, «Необратимое и доступы»).
  Зачем: релиз graft не ждёт пользователя, когда выполнены названные им условия, и не выходит сверх них по просьбе сессии
- `go run . install` → `~/bin/graft` атомарно; после изменения поведения переустановить.
  Зачем: хуки потребителей не работают на старой версии graft после правки поведения

Ловушки
- Гейт и тесты, запущенные из хука, наследуют GIT_DIR/GIT_INDEX_FILE: дочерним процессам их вычищать (`gitx.LocalEnvVars`).
  Зачем: git в тестах, запущенных из хука, не пишет в чужой индекс
- Строки, похожие на секреты, в тестах собирать конкатенацией.
  Зачем: собственная проверка секретов не отклоняет коммит graft из-за тестовых строк
