# План D п.1б: встроенные go vet и go fix -diff гейта уходят на remote_heavy в делении занятого гейта

Статус: открыт

## Вход
- git-admin 01.11: у sc2demu 1,4 CPU-ч «go test/vet в гейтах» из разбивки плана D — не тесты, а встроенный `go vet ./...` гейта graft. remote: true его не двигает.
- Замер 31.10, ноут, шаги задачи gate (встроенные): go vet 5,0 CPU-ч, из них при load ≥ 16 — 3,4; go fix -diff 2,3 / 1,7. Всего 7,3 / 5,1. По проектам при load ≥ 16 (vet + fix): sc2demu 1,6; glint 1,4; sc2go 0,6; фикстуры «main» 0,5; graft 0,3.
- Почему не уходит (internal/tasks/tasks.go):
  - gateSteps даёт встроенным шагам `&config.Task{Dir, Env}` без Remote → prepareGateStep (:1021, remoteVouched) держит их здесь;
  - splitBusyGate (:342) не считает их поводом делить гейт;
  - при проектном remote_heavy (sc2demu) splitBusyGate сразу false.
- Следствие для плана D п.1: оценка 7,9 CPU-ч при load ≥ 16 включала ≈3,4 CPU-ч встроенного vet. Рассылка `remote: true` их не снимает.

## Что сделать
- В делении занятого гейта (user remote_heavy) встроенные `go vet ./...` и `go fix -diff ./...` каждого модуля уходят на хост, как go-шаги задач с remote: true. Причина: оба только читают дерево и ничего не пишут, вывод возвращается сюда.
- Гейт с Go-модулями на занятом ноуте делится и без задач с remote: true, если встроенный vet включён.
- Обрыв пути до хоста — шаг повторяется здесь под тем же допуском, как сейчас.
- Проектный remote_heavy — отдельный вопрос (sc2demu): по замыслу проектного хоста; в этом тикете не трогать, итог — git-admin.
- README: абзац про деление гейта.
