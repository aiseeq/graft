# stats: у отказа встроенного шага гейта (gofmt -l и др.) пустая причина

Статус: в работе
Исполнитель: graft-master

## Что сделать
Находка dream-master 01.11 (тикет dream tests-review-dream): с 31.10 14 отказов gate у деревьев dream без причины в `graft stats --failures`, все — шаг `gofmt -l`.

Причина (код): шаги, которые graft делает в своём процессе, пишутся через `measureFunc` (internal/tasks/tasks.go) с reason "" — текст ошибки в stats не попадает. Ошибка gofmt к тому же не называет файлов (список только в stdout).

План: measureFunc пишет reason = текст ошибки; ошибка checkGoFmt называет первый файл и сколько ещё. Тест: отказ gofmt даёт непустую причину в записи шага.

Чем проверить: тест в internal/tasks; живой — неотформатированный файл в пробном репо, `graft gate` падает, `graft stats --failures --since 5m` показывает причину с именем файла.
